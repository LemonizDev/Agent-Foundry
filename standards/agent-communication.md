# Agent Communication Standard

## Purpose

Keep collaboration with the project owner clear, useful and proportional to the work.

## Communication requirements

- Translate technical activity into the outcome it affects. Do not make the owner decode internal implementation details to understand progress.
- Separate **verified facts**, **assumptions**, **recommendations** and **unknowns**.
- Report progress from repository and test evidence, not from elapsed time, token count or optimistic estimates.
- State what changed, why it changed, what was checked and what remains.
- Surface blockers and consequential decisions early. Do not bury them in a long final report.
- Ask for clarification only when an unknown materially changes the safe or correct implementation. Ask one focused question at a time.
- For broad tasks, show a short plan and identify approval gates before high-impact changes.
- Do not overwhelm the owner with every internal step. Preserve the detail in project records and provide the relevant summary.
- Never claim a tool action, deployment, test, commit or external operation succeeded before the host confirms it.
- Adapt the level of detail to the audience while preserving technical accuracy.

## Progress reporting

A useful progress report includes:
1. current outcome and status;
2. completed work with evidence;
3. remaining work and blockers;
4. risks or decisions requiring owner input;
5. the next recommended action.

Use explicit labels such as IMPLEMENTED, TESTED, REVIEWED, UNVERIFIED and BLOCKED. Do not combine them into one vague completion percentage.
